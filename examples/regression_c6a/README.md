# 回归案例：C6A 的过期字节数

## 事故经过（真实，非构造）

2026-11-21 我做 C6A 数据仪表盘交付。为了让页面更好看，我把 6 张截图**重新截了一遍**，但 AI 日志里那两行尺寸数字没有跟着更新：

| 位置 | 日志里写的 | 盘上真实值 |
|---|---|---|
| 截图字节数 | `226315` | `523426` |
| 单文件 HTML 字节数 | `260552` | `262608` |
| HTML sha256 前缀 | `d6e7157e` | `551ec0cc` |

提交前我自己排查时发现了，手工改掉了。但**这次是靠我记得**，不是靠工具。如果那次我忘了，AI 评语会直接指认「交付说明中的数字与实物不符」——我在 C4D 那轮就被这么指认过一次。

## 这个目录是什么

`screenshot.png` 就是那次交付的原始文件（`01_总览.png`，523426 字节，sha256 前缀 `b3cd3d32766cf149`），我把它原样搬进来当夹具。

`dek.json` 里那条 `file_size` 断言保留的是**当时的错误值 226315**。所以这是一个永久的失败用例：只要 DEK 的行为正确，它就必须 FAIL。

## 怎么用

```bash
cd examples/regression_c6a
python3 -m dek verify --root . --manifest dek.json -v
echo "exit=$?"    # 必须是 1
```

期望输出要点：
- `截图字节数（历史错误值）` → **FAIL**，并给出实际值 523426 与差值 297111
- `截图 sha256 前缀` → **PASS**
- 汇总 `VERDICT=FAIL  total=2  pass=1  fail=1`

## 它证明了什么

一个核验工具最容易出的问题是**永远报 PASS**（断言写松了）或**永远报 FAIL**（取数路径写错了）。这个案例把两种情况同时钉住：同一个文件、同一次运行，必须一条 FAIL 一条 PASS。
